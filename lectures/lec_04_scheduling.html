Today in one sentence

There is no single best order for your tasks: first decide what you want to achieve, and the right rule follows.

Monday morning, ten tasks on your list: where do you start? Companies face the same question at scale: which order on the production line, which customer order first, which project gets the team this week.

The basics: when order matters, and when it doesn’t

Four loads of laundry, one washer, one dryer

Notes

Topic: understanding scheduling problems and algorithmic solutions for optimal task ordering. Why this matters: every day you make scheduling decisions, from organizing your to-do list to managing projects. Today we learn the mathematical algorithms that can optimize these decisions.

Old agenda: scheduling fundamentals (Johnson’s rule and two-machine problems), historical context, core algorithms (EDD for deadlines, SPT for efficiency), advanced topics (dependencies, real-time scheduling, thrashing).

Goal: all laundry done as early as possible

Task  Washing  Drying
  A    40min   60min
  B    30min   80min
  C    60min   20min
  D    50min   60min

Goal: Minimize total time for washing and drying all loads

Question: An idea how to solve this?

Johnson’s rule: shortest job first or last

Rule: To find the optimal solution:

  1. Find the job with shortest duration:
    • If on Machine 1 → Schedule First
    • If on Machine 2 → Schedule Last
    • If equal → Choose randomly
  2. Remove job from list and repeat

Industrialization

  • First systematic visualization by Frederick Taylor
  • Henry Gantt develops the Gantt Chart around 1910
  • Key tool of industrial production planning
  • But no scheduling theory yet!

Question: Who knows what a Gantt Chart is?

Modern Scheduling Theory

  • RAND Corporation founded (1948)
  • Selmer Johnson publishes Johnson’s Rule in 1954
  • Beginning of modern scheduling theory
  • Many more algorithms and methods developed since

Scheduling is everywhere in professional practice

  • Project management: task dependencies, resource allocation
  • Software: CPU, threads, job queues
  • Operations: production, supply chain
  • Healthcare: patients, surgeries, staff
  • Transportation: routes, crews, maintenance

Notes

Where do we see scheduling in professional practice? These are the same optimization problems that algorithms solve: in project management (task dependencies and resource allocation), software development (CPU, thread management, job queues), operations (production and supply chain optimization), healthcare (patients, surgery planning, staff allocation) and transportation (routes, crews, maintenance).

For total time alone, the order doesn’t matter

With one person and no deadlines, every order takes the same total time.

Question: But is it that simple?

Order becomes crucial with deadlines, priorities and dependencies.

Notes

Under simple minimization of total processing time, order doesn’t matter: the total is the sum of all durations, whatever the order. As soon as we care about deadlines, waiting time, priorities or dependencies, the order matters a lot.

Question: Any ideas how to solve this?

Lawler’s algorithm: fill the schedule from the back

Rule: We can use Lawler’s Algorithm (1968)

  1. Consider all tasks without successors
  2. Choose the one with latest deadline
  3. Schedule the task last
  4. Remove it from the network and start again

Question: What’s the maximum delay?

Waiting time with dependencies has no fast exact solution

  • NP-hard: no known algorithm solves it efficiently
  • True for most scheduling problems
  • In practice we use heuristics, good rules without a guarantee

Notes

Shortest processing time with predecessors cannot be solved in polynomial time, it is NP-hard. This is true for most scheduling problems. We can use heuristics, though: rules that give good, but not provably optimal schedules.

EDD in real time: switch only for an earlier deadline

Rule:

  • Always work on the task with the earliest deadline
  • A new task with an earlier deadline interrupts the current one
  • Otherwise, stick to the current task

Notes

Equal deadline: if a new task has the same deadline as the current task, you can choose either. But because of the cost of context switching, you should stick with the current task.

Thrashing: switching so much that nothing gets done

  • Excessive context switching
  • Organization overhead exceeds productivity
  • Maximum activity, minimum output

Warning signs of thrashing

  • Increasing stress levels
  • Declining quality
